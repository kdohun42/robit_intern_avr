# 주제 1. ATmega128에서 I2C 통신의 SCL과 SDA

# 1. I2C란?

I2C는 Inter-Integrated Circuit의 약자이다.

마이크로컨트롤러와 센서, LCD, EEPROM 등의 주변장치가 통신할 때 사용하는 동기식 직렬 통신 방식이다.

I2C는 다음 두 개의 통신선을 사용한다.

1. SCL

   Serial Clock Line의 약자이다.

   데이터 전송 시점을 맞추기 위한 클럭 신호선이다.

2. SDA

   Serial Data Line의 약자이다.

   장치 주소와 실제 데이터를 송수신하는 데이터 신호선이다.

I2C는 데이터 신호와 별도로 클럭 신호를 사용한다.

송신 장치와 수신 장치는 SCL 신호를 기준으로 SDA에 실린 데이터를 읽는다.

따라서 송신 장치와 수신 장치가 데이터 전송 시점을 맞출 수 있다.

I2C는 하나의 SCL과 SDA 선에 여러 장치를 함께 연결할 수 있다.

각 장치는 고유한 주소를 사용하여 구분한다.

7비트 주소는 0부터 127까지 표현할 수 있지만 일부 주소는 특수한 목적으로 예약되어 있다.

따라서 실제로 사용할 수 있는 장치 주소의 수는 128개보다 적다.

## 버스 방식

버스 방식은 하나의 공통 전송 경로를 여러 장치가 함께 사용하는 연결 방식이다.

# 2. SCL과 SDA의 역할

## SCL의 역할

SCL은 I2C 통신의 기준 시간을 제공하는 클럭 신호선이다.

일반적으로 통신을 시작하는 Controller가 SCL 클럭을 생성한다.

수신 장치는 SCL 신호를 기준으로 SDA의 값을 읽는다.

한 개의 데이터 비트를 전송할 때마다 SCL에는 한 번의 클럭 펄스가 발생한다.

## SDA의 역할

SDA는 장치 주소, 읽기와 쓰기 방향, 실제 데이터를 전송하는 양방향 데이터 신호선이다.

통신 방향에 따라 Controller 또는 Target 장치가 SDA를 제어할 수 있다.

## Controller

기존에는 Master라고 불렀다.

통신을 시작하고 일반적으로 SCL 클럭을 생성하는 장치이다.

## Target

기존에는 Slave라고 불렀다.

자신의 주소가 수신되면 Controller의 요청에 응답하는 장치이다.

# 3. SCL과 SDA의 전기적 특성

I2C의 SCL과 SDA는 일반적인 출력 핀처럼 HIGH와 LOW를 모두 직접 출력하지 않는다.

주로 오픈 드레인 방식으로 동작한다.

각 장치는 신호선을 LOW로 당길 수 있다.

HIGH 상태는 외부 풀업 저항을 통해 만들어진다.

```text
VCC
 │
 ├── 풀업 저항 ── SCL
 │
 └── 풀업 저항 ── SDA
```

버스에 연결된 모든 장치가 신호선을 제어하지 않으면 풀업 저항에 의해 HIGH가 된다.

하나의 장치라도 신호선을 LOW로 당기면 전체 버스는 LOW가 된다.

이 구조를 사용하면 여러 장치가 하나의 신호선을 함께 사용할 때 출력 충돌을 줄일 수 있다.

또한 여러 Controller가 동시에 통신을 시도할 때 중재 기능을 사용할 수 있다.

풀업 저항값은 다음 조건에 따라 결정한다.

1. 전원전압
2. 배선 길이
3. 통신 속도
4. 버스 정전용량

일반적인 실습 회로에서는 4.7kΩ의 풀업 저항을 자주 사용한다.

하지만 회로 조건에 따라 다른 저항값이 필요할 수 있다.

# 4. I2C 통신의 기본 원리

I2C 통신은 일반적으로 다음 순서로 진행된다.

```text
START 조건
   ↓
장치 주소와 R/W 비트
   ↓
ACK 또는 NACK
   ↓
8비트 데이터
   ↓
ACK 또는 NACK
   ↓
STOP 조건
```

## 대기 상태

통신이 진행되지 않을 때 SCL과 SDA는 모두 HIGH 상태이다.

## START 조건

SCL이 HIGH인 상태에서 SDA가 HIGH에서 LOW로 변경되면 START 조건이 된다.

START 조건이 발생하면 버스에 연결된 장치들은 새로운 통신이 시작되었다는 것을 인식한다.

## 장치 주소와 R/W 비트

START 조건 이후에는 일반적으로 7비트 장치 주소와 1비트 R/W 값이 전송된다.

### R/W 비트가 0인 경우

Controller가 Target 장치에 데이터를 쓴다는 의미이다.

### R/W 비트가 1인 경우

Controller가 Target 장치에서 데이터를 읽는다는 의미이다.

## ACK와 NACK

주소 또는 데이터 8비트가 전송된 후 9번째 클럭에서 수신 장치가 응답한다.

### ACK

SDA를 LOW로 만들어 데이터가 정상적으로 수신되었다는 것을 알린다.

### NACK

SDA가 HIGH로 유지된다.

데이터를 정상적으로 받지 못했거나 데이터 전송을 종료한다는 의미로 사용한다.

## 데이터 전송

데이터는 한 번에 8비트씩 전송된다.

I2C에서는 최상위 비트인 MSB부터 전송한다.

```text
D7 → D6 → D5 → D4 → D3 → D2 → D1 → D0
```

각 데이터 바이트를 전송한 후에는 ACK 또는 NACK 비트가 추가된다.

## STOP 조건

SCL이 HIGH인 상태에서 SDA가 LOW에서 HIGH로 변경되면 STOP 조건이 된다.

STOP 조건이 발생하면 현재 통신이 종료되고 버스는 다시 대기 상태가 된다.

# 5. I2C 데이터의 변경 시점

일반적인 데이터 전송 중에는 SCL이 HIGH인 동안 SDA의 값이 안정적으로 유지되어야 한다.

SDA의 데이터는 원칙적으로 SCL이 LOW일 때 변경한다.

## SCL이 LOW인 경우

SDA를 다음 데이터 비트로 변경할 수 있다.

## SCL이 HIGH인 경우

SDA의 현재 데이터 값을 유지해야 한다.

## SCL이 HIGH이고 SDA가 HIGH에서 LOW로 변하는 경우

START 조건을 의미한다.

## SCL이 HIGH이고 SDA가 LOW에서 HIGH로 변하는 경우

STOP 조건을 의미한다.

# 6. I2C 통신의 장단점

## 장점

1. SCL과 SDA 두 개의 선만 사용한다.
2. 하나의 버스에 여러 장치를 연결할 수 있다.
3. 장치 주소를 이용하여 통신 대상을 선택할 수 있다.
4. ACK를 통해 데이터 수신 여부를 확인할 수 있다.
5. 센서, LCD, EEPROM 등의 주변장치 연결에 적합하다.
6. 클럭 신호를 공유하므로 데이터 전송 시점을 맞추기 쉽다.

## 단점

1. SCL과 SDA에 풀업 저항이 필요하다.
2. 배선이 길어지면 버스 정전용량이 증가한다.
3. 연결된 장치가 많아지면 통신이 불안정해질 수 있다.
4. SPI와 비교하면 일반적으로 통신 속도가 느리다.
5. 같은 주소를 사용하는 장치를 하나의 버스에 바로 연결하기 어렵다.
6. 버스에 문제가 발생하면 여러 장치의 통신이 함께 영향을 받을 수 있다.
7. 통신 속도가 증가할수록 배선과 풀업 저항 설계가 중요해진다.

# 7. ATmega128에서 I2C 사용

ATmega128에서는 I2C 기능을 TWI라고 부른다.

TWI는 Two-Wire Serial Interface의 약자이다.

## I2C 핀

ATmega128에서 사용하는 I2C 핀은 다음과 같다.

### PD0

SCL 신호선으로 사용한다.

### PD1

SDA 신호선으로 사용한다.

```text
[ATmega128]                [I2C 장치]

PD0 / SCL   <------------> SCL
PD1 / SDA   <------------> SDA
VCC         -------------> VCC
GND         -------------> GND
```

SCL과 SDA에는 풀업 저항을 연결해야 한다.

ATmega128과 I2C 장치는 공통 GND를 사용해야 한다.

# 8. ATmega128의 주요 TWI 레지스터

## TWBR

TWBR은 TWI Bit Rate Register의 약자이다.

ATmega128이 Controller로 동작할 때 SCL의 통신 속도를 설정한다.

### SCL 주파수 계산

```text
SCL 주파수
=
CPU 클럭
÷
(16 + 2 × TWBR × Prescaler)
```

TWSR의 프리스케일러 비트가 00이면 Prescaler는 1이다.

16MHz 클럭과 프리스케일러 1에서 약 100kHz의 SCL을 사용하려면 TWBR에 72를 설정할 수 있다.

## TWCR

TWCR은 TWI Control Register의 약자이다.

TWI 통신의 시작, 종료, 활성화와 인터럽트를 제어한다.

### TWINT

TWI 작업 완료 여부를 나타내는 플래그이다.

TWINT에 1을 기록하면 플래그가 지워지고 설정된 TWI 동작이 시작된다.

### TWEA

ACK 응답을 활성화한다.

### TWSTA

START 조건을 발생시킨다.

### TWSTO

STOP 조건을 발생시킨다.

### TWWC

데이터 충돌 여부를 확인한다.

### TWEN

TWI 기능을 활성화한다.

### TWIE

TWI 인터럽트를 활성화한다.

## TWSR

TWSR은 TWI Status Register의 약자이다.

현재 TWI 통신 상태와 비트레이트 프리스케일러를 확인한다.

### TWS7부터 TWS3

현재 TWI 통신 상태 코드를 저장한다.

### TWPS1과 TWPS0

SCL 프리스케일러를 설정한다.

TWSR의 상태 코드를 이용하면 다음 내용을 확인할 수 있다.

1. START 조건 발생
2. 주소 전송
3. ACK 수신
4. NACK 수신
5. 중재 상태

## TWDR

TWDR은 TWI Data Register의 약자이다.

송신할 데이터 또는 수신된 데이터를 저장한다.

데이터를 송신할 때는 TWDR에 값을 기록한다.

데이터 수신이 완료된 후에는 TWDR의 값을 읽는다.

## TWAR

TWAR은 TWI Address Register의 약자이다.

ATmega128이 Target 장치로 동작할 때 자신의 주소를 설정한다.

7비트 주소는 레지스터의 상위 7비트에 저장한다.

ATmega128이 Controller로만 동작하면 반드시 설정할 필요는 없다.

# 9. ATmega128의 I2C 데이터 전송 과정

```text
TWI 초기화
   ↓
START 조건 발생
   ↓
장치 주소와 Write 또는 Read 비트 전송
   ↓
ACK 확인
   ↓
데이터 송수신
   ↓
ACK 또는 NACK 확인
   ↓
STOP 조건 발생
```

I2C LCD에는 PCF8574 등의 I/O 확장 모듈이 부착된 경우가 많다.

ATmega128은 I2C 주소를 이용하여 확장 모듈에 데이터를 전송한다.

확장 모듈은 LCD의 제어핀과 데이터핀을 대신 제어한다.

# 주제 2. UART 통신에서 사용하는 RS-232와 RS-485

# 1. UART란?

UART는 Universal Asynchronous Receiver/Transmitter의 약자이다.

병렬 데이터를 직렬 데이터로 변환하여 송신한다.

수신된 직렬 데이터는 다시 병렬 데이터로 변환한다.

UART는 별도의 클럭선을 사용하지 않는 비동기식 직렬 통신이다.

송신 장치와 수신 장치는 다음 설정을 동일하게 맞춰야 한다.

1. Baud Rate
2. 데이터 비트 수
3. 패리티 사용 여부
4. 정지 비트 수

일반적으로 사용하는 `9600, 8-N-1`은 다음 의미를 가진다.

1. 통신 속도는 9600bps이다.
2. 데이터 비트는 8비트이다.
3. 패리티는 사용하지 않는다.
4. 정지 비트는 1비트이다.

# 2. 직렬 통신

직렬 통신은 여러 비트의 데이터를 하나 또는 적은 수의 신호선을 통해 시간 순서대로 전송하는 방식이다.

병렬 통신은 여러 비트를 동시에 전송하기 때문에 많은 핀이 필요하다.

직렬 통신은 적은 수의 핀으로 데이터를 전송할 수 있다.

# 3. UART 데이터 프레임

UART의 기본 데이터 프레임은 다음과 같다.

```text
대기 상태
   ↓
시작 비트
   ↓
데이터 비트
   ↓
패리티 비트
   ↓
정지 비트
```

패리티 비트는 설정에 따라 사용하지 않을 수 있다.

## 시작 비트

새로운 데이터의 전송이 시작되었다는 것을 알린다.

일반적으로 LOW 상태이다.

## 데이터 비트

실제로 전송되는 데이터이다.

UART에서는 일반적으로 LSB부터 전송한다.

## 패리티 비트

선택적으로 사용하며 간단한 오류 검출에 사용한다.

## 정지 비트

하나의 데이터 전송이 종료되었다는 것을 알린다.

일반적으로 HIGH 상태이다.

# 4. UART 주요 레지스터

ATmega128에는 USART0과 USART1이 있다.

레지스터 이름의 n은 USART 번호 0 또는 1을 의미한다.

## UDRn

UDRn은 USART Data Register의 약자이다.

송신할 데이터와 수신된 데이터를 저장한다.

송신할 때는 UDRn에 데이터를 기록한다.

수신할 때는 UDRn의 값을 읽는다.

송신 레지스터와 수신 레지스터는 내부적으로 구분되지만 같은 주소를 사용한다.

## UCSRnA

UCSRnA는 USART의 현재 상태를 확인하는 레지스터이다.

### RXCn

수신 데이터가 준비되었는지 확인한다.

### TXCn

데이터 전송이 완전히 끝났는지 확인한다.

### UDREn

송신 버퍼가 비어 있는지 확인한다.

### FEn

프레임 오류가 발생했는지 확인한다.

### DORn

데이터 오버런이 발생했는지 확인한다.

### UPEn

패리티 오류가 발생했는지 확인한다.

### U2Xn

더블 스피드 모드를 설정한다.

## UCSRnB

UCSRnB는 송신, 수신과 관련 인터럽트를 설정하는 레지스터이다.

### RXCIEn

수신 완료 인터럽트를 활성화한다.

### TXCIEn

송신 완료 인터럽트를 활성화한다.

### UDRIEn

송신 버퍼 비움 인터럽트를 활성화한다.

### RXENn

수신 기능을 활성화한다.

### TXENn

송신 기능을 활성화한다.

### UCSZn2

데이터 비트 크기를 설정할 때 사용한다.

## UCSRnC

UCSRnC는 통신 방식과 데이터 프레임 형식을 설정한다.

### UMSELn

동기 통신 또는 비동기 통신을 선택한다.

### UPMn1과 UPMn0

패리티 사용 방식을 설정한다.

### USBSn

정지 비트의 개수를 설정한다.

### UCSZn1과 UCSZn0

데이터 비트의 크기를 설정한다.

### UCPOLn

동기식 통신에서 클럭 극성을 설정한다.

## UBRRn

UBRRn은 USART Baud Rate Register의 약자이다.

UART 통신 속도를 설정한다.

16MHz에서 일반 속도 비동기 통신으로 9600bps를 사용할 경우 UBRR 값은 약 103이다.

# 5. UART와 RS-232, RS-485의 관계

UART와 RS-232, RS-485는 같은 개념이 아니다.

## UART

데이터를 어떤 프레임 형식으로 송수신할 것인지 담당한다.

## RS-232

전압과 배선 등의 전기적 신호 방식을 정의한다.

## RS-485

차동 신호와 버스 연결 등의 전기적 신호 방식을 정의한다.

```
ATmega128 UART
      ↓
RS-232 또는 RS-485 트랜시버
      ↓
통신 케이블
      ↓
상대 장치
```

ATmega128의 TX와 RX 핀은 MCU 논리전압을 사용한다.

따라서 RS-232 또는 RS-485 통신선에 직접 연결하면 안 된다.

RS-232 통신에는 MAX232와 같은 트랜시버가 필요하다.

RS-485 통신에는 MAX485와 같은 트랜시버가 필요하다.

# 6. RS-232 통신

## RS-232란?

RS-232는 직렬 통신을 위한 전기적 인터페이스 규격이다.

하나의 신호선을 GND 기준으로 측정하는 단일 종단 방식을 사용한다.

주로 두 장치 사이의 점대점 통신에 사용한다.

TX와 RX 신호선이 분리되어 있어 기본적으로 전이중 통신이 가능하다.

## RS-232의 특징

1. TX, RX, GND를 이용한다.
2. 두 장치 사이의 점대점 통신에 적합하다.
3. 송신과 수신을 동시에 수행할 수 있다.
4. 일반적으로 한 송신기와 한 수신기를 연결한다.
5. GND 기준의 단일 종단 신호를 사용한다.
6. 컴퓨터, 계측기와 설정용 콘솔에 사용한다.
7. MCU와 연결할 때 전압 변환 회로가 필요하다.

## RS-232의 장점

1. 구조가 단순하다.
2. 구현하기 쉽다.
3. 송신과 수신을 동시에 수행할 수 있다.
4. 점대점 통신에서 장치 구성이 간단하다.
5. 오래된 컴퓨터와 산업용 장비에서 널리 사용한다.
6. 별도의 송수신 방향 제어가 필요하지 않다.

## RS-232의 단점

1. 외부 잡음에 비교적 약하다.
2. 장거리 통신에 적합하지 않다.
3. 여러 장치를 하나의 버스에 연결하기 어렵다.
4. MAX232와 같은 전압 변환기가 필요하다.
5. 접지 전위차가 커지면 통신 오류가 발생할 수 있다.

# 7. RS-485 통신

## RS-485란?

RS-485는 두 개의 신호선 A와 B 사이의 전압 차이를 이용하는 차동 통신 방식이다.

수신기는 각 선의 절대 전압보다 A와 B 사이의 전압 차이를 확인한다.

두 선에 같은 방향으로 잡음이 발생하면 차동 입력 과정에서 잡음의 일부가 제거된다.

따라서 RS-232보다 잡음이 많은 환경과 긴 배선에 적합하다.

# 8. RS-485 연결 방식

## 2선식 반이중 통신

가장 일반적인 RS-485 연결 방식이다.

A와 B 선을 송신과 수신에 함께 사용한다.

```
A ───────────────── A ───────────────── A
B ───────────────── B ───────────────── B
```

한 시점에는 하나의 장치만 송신해야 한다.

MAX485를 사용할 때는 DE와 `/RE` 핀을 이용하여 송신과 수신 모드를 전환한다.

### DI

UART의 TX 데이터를 입력받는다.

### RO

수신된 데이터를 UART의 RX로 출력한다.

### DE

송신 드라이버를 활성화한다.

### `/RE`

수신기를 활성화한다.

### A와 B

RS-485 차동 통신선이다.

## 4선식 전이중 통신

송신용 차동선과 수신용 차동선을 별도로 사용한다.

송신과 수신을 동시에 수행할 수 있다.

하지만 배선 수와 회로 구성이 증가한다.

# 9. RS-485 종단 저항

긴 케이블이나 빠른 통신 속도에서는 신호가 케이블 끝에서 반사될 수 있다.

신호 반사는 통신 오류의 원인이 된다.

이를 줄이기 위해 버스의 양 끝에 종단 저항을 연결한다.

일반적인 RS-485 꼬임선에서는 약 120Ω의 종단 저항을 많이 사용한다.

종단 저항은 모든 장치에 연결하지 않고 버스의 물리적인 양 끝에 연결한다.

# 10. RS-485 바이어스 저항

RS-485 버스에서 모든 송신기가 비활성화되면 A와 B의 전압 차이가 불안정해질 수 있다.

이때 풀업 저항과 풀다운 저항을 이용하여 통신선의 기본 상태를 정할 수 있다.

이 기능을 Fail-safe biasing이라고 한다.

일부 RS-485 트랜시버에는 내부 Fail-safe 기능이 포함되어 있다.

따라서 사용하는 부품의 데이터시트를 확인해야 한다.

# 11. RS-485의 특징

1. A와 B 두 선의 전압 차이를 이용한다.
2. 여러 장치를 하나의 버스에 연결할 수 있다.
3. 일반적으로 꼬임선을 사용한다.
4. 2선식 반이중과 4선식 전이중 구성이 가능하다.
5. 반이중 방식에서는 송수신 방향 제어가 필요하다.
6. 긴 배선이나 빠른 통신에서는 종단 저항이 중요하다.
7. 전기적 잡음이 많은 산업 환경에 적합하다.
8. 장치 주소와 데이터 형식은 별도의 프로토콜로 정해야 한다.

# 12. RS-485의 장단점

## 장점

1. 차동 신호를 사용하여 잡음에 강하다.
2. RS-232보다 장거리 통신에 유리하다.
3. 하나의 버스에 여러 장치를 연결할 수 있다.
4. 공장 자동화와 모터 제어에 적합하다.
5. 센서 네트워크에 사용할 수 있다.
6. 장치 간 GND 전위차의 영향을 비교적 적게 받는다.
7. Modbus RTU와 Dynamixel 통신 등에 활용할 수 있다.

## 단점

1. RS-232보다 회로 구성이 복잡하다.
2. MAX485와 같은 RS-485 트랜시버가 필요하다.
3. 2선식 반이중 통신에서는 방향을 제어해야 한다.
4. 여러 장치가 동시에 송신하지 않도록 관리해야 한다.
5. 배선과 종단 저항이 잘못되면 신호 반사가 발생한다.
6. RS-485 자체에는 장치 주소와 데이터 형식이 정의되어 있지 않다.

# 13. RS-232와 RS-485의 차이

## 신호 방식

RS-232는 단일 종단 방식을 사용한다.

RS-485는 차동 방식을 사용한다.

## 주요 신호선

RS-232는 TX, RX, GND를 사용한다.

RS-485는 A와 B를 사용한다.

## 연결 방식

RS-232는 일반적으로 두 장치 사이의 점대점 통신에 사용한다.

RS-485는 여러 장치를 연결할 수 있는 버스 방식에 사용한다.

## 통신 방식

RS-232는 일반적으로 전이중 통신을 사용한다.

RS-485는 2선식 반이중 또는 4선식 전이중 통신을 사용할 수 있다.

## 통신 거리

RS-232는 비교적 짧은 거리의 통신에 사용한다.

RS-485는 비교적 긴 거리의 통신에 사용할 수 있다.

## 연결 장치 수

RS-232는 일반적으로 두 장치를 연결한다.

RS-485는 하나의 버스에 여러 장치를 연결할 수 있다.

## MCU 연결 부품

RS-232는 MAX232 계열의 트랜시버를 사용한다.

RS-485는 MAX485 계열의 트랜시버를 사용한다.

## 방향 제어

RS-232는 일반적으로 별도의 방향 제어가 필요하지 않다.

RS-485의 2선식 반이중 방식은 송수신 방향을 제어해야 한다.
