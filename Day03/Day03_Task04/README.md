## 1. 개요 (Overview)

본 과제는 ATmega128 마이크로컨트롤러의 USART 하드웨어 기능을 사용하지 않고, GPIO 출력과 시간 지연을 이용하여 UART 통신을 직접 구현하는 것을 목표로 함.

PE1 핀을 UART 송신 핀인 TX로 사용하고, PE0 핀을 UART 수신 핀인 RX로 사용함. UART 통신의 시작 비트, 8개의 데이터 비트, 정지 비트를 프로그램에서 직접 출력하여 9600bps 속도의 직렬 통신을 구현함.

메인 반복문에서는 `"HelloWorld!\r\n"` 문자열을 1초마다 소프트웨어 UART 방식으로 전송함.

### 핵심 목표

* GPIO를 이용한 UART 송신 신호 직접 생성
* UART 프레임의 시작 비트, 데이터 비트, 정지 비트 이해
* `_delay_us()`를 이용한 9600bps 비트 시간 구현
* LSB 우선 방식의 8비트 데이터 전송
* 문자열을 한 문자씩 UART 방식으로 전송
* 하드웨어 USART와 소프트웨어 UART의 차이 이해
* PE0과 PE1을 이용한 RX 및 TX 핀 구성

## 3. 하드웨어 구성 및 핀 맵 (Hardware Structure)

### Pin Configuration

```text
[ATmega128]                    [Target Component]

PE0 / Software RX   <--------  USB to UART 모듈 TX
PE1 / Software TX   -------->  USB to UART 모듈 RX
GND                 -------->  USB to UART 모듈 GND
```

### 주요 회로 특징

* **전원:** ATmega128 개발보드에 5V DC 안정화 전원을 공급함.
* **TX 핀:** PE1을 출력으로 설정하여 UART 송신 신호를 직접 생성함.
* **RX 핀:** PE0을 입력으로 설정하여 UART 수신 신호를 읽도록 구성함.
* **초기 TX 상태:** UART 통신 대기 상태는 HIGH이므로 PE1을 초기 상태에서 HIGH로 설정함.
* **교차 연결:** ATmega128의 TX 핀은 USB to UART 모듈의 RX 핀에 연결함.
* **공통 접지:** ATmega128과 USB to UART 모듈의 GND를 공통으로 연결함.
* **통신 속도:** PC 시리얼 터미널의 통신 속도를 9600bps로 설정함.
* **통신 형식:** 데이터 8비트, 패리티 없음, 정지 비트 1개로 설정함.
* **주의사항:** 소프트웨어 UART는 프로그램 실행 시간에 따라 비트 시간이 달라질 수 있으므로 인터럽트나 추가 연산이 통신에 영향을 줄 수 있음.

## 5. 핵심 코드 및 레지스터 설정 (Key Implementation)

### CPU 동작 주파수 설정

```c
#define F_CPU 16000000UL
```

ATmega128의 CPU 동작 주파수를 16MHz로 정의함.

`_delay_us()`와 `_delay_ms()` 함수는 `F_CPU` 값을 기준으로 지연 시간을 계산하므로 실제 보드의 클럭과 동일하게 설정해야 함.

### TX와 RX 핀 초기화

```c
void init(void)
{
	DDRE = 0b00000010;
	PORTE = 0b00000010;
}
```

`DDRE` 레지스터를 이용하여 PE0은 입력으로, PE1은 출력으로 설정함.

```text
DDRE = 00000010
             ↑
           PE1 = 1, 출력
           PE0 = 0, 입력
```

`PORTE`의 PE1 비트를 1로 설정하여 TX 핀의 초기 상태를 HIGH로 설정함.

UART 통신에서는 데이터를 전송하지 않는 대기 상태를 논리 HIGH로 유지함.

|  핀  |  방향 | 기능            |
| :-: | :-: | :------------ |
| PE0 |  입력 | 소프트웨어 UART RX |
| PE1 |  출력 | 소프트웨어 UART TX |

### UART 전송 프레임

본 코드에서 한 문자 전송은 다음 순서로 이루어짐.

```text
대기 상태
   ↓
시작 비트
   ↓
데이터 비트 0
   ↓
데이터 비트 1
   ↓
...
   ↓
데이터 비트 7
   ↓
정지 비트
   ↓
대기 상태
```

사용하는 프레임 형식은 다음과 같음.

| 항목     |     설정    |
| :----- | :-------: |
| 시작 비트  |  1비트, LOW |
| 데이터 비트 |    8비트    |
| 전송 순서  |   LSB 먼저  |
| 패리티 비트 |     없음    |
| 정지 비트  | 1비트, HIGH |

### 9600bps 비트 시간 계산

9600bps는 1초 동안 9600개의 비트를 전송한다는 의미임.

한 비트의 시간은 다음과 같이 계산됨.

```text
1비트 시간 = 1초 ÷ 9600
           ≒ 0.00010417초
           ≒ 104.17µs
```

코드에서는 한 비트를 약 104µs 동안 유지함.

```c
_delay_us(104);
```

이 지연을 시작 비트, 각 데이터 비트, 정지 비트마다 적용하여 9600bps 통신 속도를 구현함.

### 한 바이트 송신 함수

```c
void TX(unsigned char data)
{
	PORTE = 0b00000000;
	_delay_us(104);

	for (int i = 0; i < 8; i++)
	{
		if (data & (1 << i))
		{
			PORTE |= (1 << PE1);
		}
		else
		{
			PORTE &= ~(1 << PE1);
		}

		_delay_us(104);
	}

	PORTE = 0b00000010;
	_delay_us(104);
}
```

`TX()` 함수는 한 문자를 UART 프레임 형식으로 변환하여 PE1 핀으로 출력함.

### 시작 비트 전송

```c
PORTE = 0b00000000;
_delay_us(104);
```

UART 전송을 시작하기 위해 PE1을 LOW로 변경함.

시작 비트는 반드시 LOW이며, 한 비트 시간인 약 104µs 동안 유지함.

```text
TX 대기 상태: HIGH
시작 비트:    LOW
```

### 데이터 비트 전송

```c
for (int i = 0; i < 8; i++)
{
	if (data & (1 << i))
	{
		PORTE |= (1 << PE1);
	}
	else
	{
		PORTE &= ~(1 << PE1);
	}

	_delay_us(104);
}
```

8비트 데이터를 0번 비트부터 7번 비트까지 순서대로 확인함.

```c
data & (1 << i)
```

현재 확인하는 비트가 1이면 PE1을 HIGH로 설정하고, 현재 비트가 0이면 PE1을 LOW로 설정함.

반복문의 `i`가 0부터 시작하므로 데이터는 최하위 비트인 LSB부터 전송됨.

예를 들어 문자 `'A'`의 ASCII 값은 `0x41`이며 2진수로 다음과 같음.

```text
'A' = 0x41 = 01000001
```

UART에서는 LSB부터 전송하므로 다음 순서로 출력됨.

```text
비트 번호: 0 1 2 3 4 5 6 7
전송 값:   1 0 0 0 0 0 1 0
```

### 정지 비트 전송

```c
PORTE = 0b00000010;
_delay_us(104);
```

8개의 데이터 비트를 모두 전송한 후 PE1을 HIGH로 설정함.

정지 비트는 HIGH 상태이며 한 비트 시간 동안 유지함.

정지 비트 전송 후에도 PE1이 HIGH로 유지되므로 다음 데이터가 전송될 때까지 UART 대기 상태가 됨.

### 문자열 전송 함수

```c
void TX_string(char *data)
{
	while (*data != '\0')
	{
		TX(*data++);
	}
}
```

문자열의 끝을 나타내는 널 문자 `'\0'`을 만날 때까지 한 문자씩 `TX()` 함수로 전달함.

`*data`는 현재 문자를 의미하고, `data++`는 다음 문자의 주소로 이동하는 것을 의미함.

예를 들어 다음 문자열을 전송하는 경우,

```c
TX_string("HelloWorld!\r\n");
```

각 문자가 다음과 같이 순서대로 전송됨.

```text
'H' → 'e' → 'l' → 'l' → 'o'
→ 'W' → 'o' → 'r' → 'l' → 'd'
→ '!' → '\r' → '\n'
```

`\r`은 커서를 현재 줄의 처음으로 이동시키고, `\n`은 다음 줄로 이동시키는 제어 문자임.

### 문자열 반복 전송

```c
while (1)
{
	TX_string("HelloWorld!\r\n");
	_delay_ms(1000);
}
```

무한 반복문 안에서 `"HelloWorld!"` 문자열을 전송함.

문자열 전송이 완료되면 1000ms 동안 대기한 후 같은 문자열을 다시 전송함.

따라서 PC 시리얼 터미널에는 약 1초 간격으로 문자열이 반복 출력됨.

### 소프트웨어 UART 수신 원리

코드의 `RX()` 함수는 PE0에서 UART 데이터를 수신하기 위한 함수임.

```c
while (PINE & 0b00000001)
{
}
```

PE0이 LOW가 될 때까지 기다려 시작 비트를 감지함.

```c
_delay_us(52);
```

시작 비트의 중앙에서 신호를 확인하기 위해 한 비트 시간의 절반인 약 52µs 동안 대기함.

```c
if (PINE & 0b00000001)
{
	continue;
}
```

52µs 후 PE0이 다시 HIGH이면 정상적인 시작 비트가 아니라고 판단하고 수신을 다시 시도함.

이후 104µs 간격으로 PE0의 값을 확인하여 8개의 데이터 비트를 읽도록 구성함.

```c
if (PINE & 0b00000001)
{
	data |= (1 << i);
}
```

PE0이 HIGH이면 해당 비트를 1로 설정하고, LOW이면 초기값 0을 그대로 유지함.

### RX 함수의 현재 문제점

현재 코드의 `RX()` 함수에서는 `data` 변수가 `while` 반복문 내부에 선언되어 있음.

```c
while (1)
{
	unsigned char data = 0b00000000;
```

하지만 반복문이 끝난 뒤 다음 코드에서 `data`를 반환하려고 함.

```c
return data;
```

이 위치에서는 반복문 내부에서 선언한 `data` 변수에 접근할 수 없으므로 컴파일 오류가 발생할 수 있음.

또한 중괄호 위치로 인해 정지 비트 확인 부분이 반복문 밖에 위치함.

`data` 변수는 함수의 시작 부분에 선언하고, 정지 비트를 확인한 후 반환하도록 구조를 수정해야 함.

수정 예시는 다음과 같음.

```c
unsigned char RX(void)
{
	unsigned char data;

	while (1)
	{
		data = 0;

		while (PINE & (1 << PE0))
		{
		}

		_delay_us(52);

		if (PINE & (1 << PE0))
		{
			continue;
		}

		for (int i = 0; i < 8; i++)
		{
			_delay_us(104);

			if (PINE & (1 << PE0))
			{
				data |= (1 << i);
			}
		}

		_delay_us(104);

		if (PINE & (1 << PE0))
		{
			return data;
		}
	}
}
```

현재 `main()` 함수에서는 `RX()` 함수를 호출하지 않으므로 프로그램의 실제 동작은 문자열 송신 기능만 사용함.


문자열은 약 1초 간격으로 반복 출력됨.

### 문자 한 개의 전송 구조

문자 하나는 총 10비트로 전송됨.

```text
시작 비트 1개
+
데이터 비트 8개
+
정지 비트 1개
=
총 10비트
```

9600bps에서 문자 한 개의 전송 시간은 다음과 같음.

```text
104µs × 10비트
≒ 1040µs
≒ 1.04ms
```

`"HelloWorld!\r\n"`은 총 13개의 문자로 구성되어 있으므로 전체 문자열의 전송 시간은 약 다음과 같음.

```text
1.04ms × 13
≒ 13.52ms
```

문자열 전송 후 1000ms의 지연이 추가되므로 실제 출력 주기는 약 1.01초가 됨.

3. PE1 출력 신호를 USB to UART 모듈에 연결하여 문자열 출력 여부를 확인함.
4. 시리얼 터미널을 9600bps, 8비트, 패리티 없음, 정지 비트 1개로 설정하여 동작을 확인함.
5. 오실로스코프 또는 로직 분석기를 이용하여 시작 비트, 데이터 비트, 정지 비트의 파형을 확인함.
6. ASCII 코드에 따라 문자가 LSB부터 정상적으로 전송되는지 확인함.
7. RX 함수의 변수 범위 및 정지 비트 검사 위치를 직접 수정하고 검증함.
8. AI가 제시한 내용을 그대로 사용하지 않고 코드의 목적과 실제 하드웨어 환경에 맞게 수정하고 검증함.
